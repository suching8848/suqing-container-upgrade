# 测试范围与复核方法

## 已知验证边界

- 目标版本为 Project Zomboid Build 42.21 单人。维护者已确认 v1.0.0 在个人单人环境中使用正常。
- 游戏内检查覆盖代表性容器、逐档强化、还原返料和相关容量显示；不宣称 168 个支持 ID 全部逐件实测，也不扩大为所有装弹、换位组合或保存重进场景均已验证。
- 开发阶段另使用本机游戏 JAR 的脚本解析与 Kahlua 运行时进行离线回归，覆盖名单、材料事务、旧记录、换位、尺寸转换、动态容量和返料失败路径。离线 fixture 验证不等于启动游戏、真实存档持久化或画面验证。
- 多人和专用服务器未验证；当前代码在客户端或服务器环境拒绝强化、还原前置检查。本版不承诺联机可用。

## 建议的游戏内复核

使用备份后的单人测试世界，只启用一份本模组。每项记录原始规格、操作后的物品状态和材料差额。

1. **普通轻包**：卸下、清空并放入主物品栏，逐档检查Ⅰ至Ⅴ的技能门槛、实际扣料、容量与减重。测试材料不足、旧档位点击、取消动作及满级拒绝。
2. **重包与特殊容器**：核对满级 46–48 的重包、胸挂尺寸限制、弹带过滤和肩挂枪套 2 弹匣限制。原有换弹或自动装弹功能应分别按原模组要求测试。
3. **水袋类**：留少量液体时应拒绝强化和还原；完全排空后再操作。装回液体后，储水升数与液体机制应保持原值。
4. **原生换位与尺寸转换**：使用名单内动作，检查强化、内容物、收藏、改名和穿戴状态。前后换位的目标槽被另一件包占用时应拒绝，不应把另一件包挤掉或丢地。
5. **动态与高原生容量**：检查浣熊市沙盒容量与角色特性只计算一次，以及指定原生高容量包的物理容量不被降低。基础值已经达到普通Ⅴ档时不应再收费。
6. **还原与付款账本**：核对实际新支付的一半返料，分别向下取整；线按用量返还，可能得到部分线轴。未记账旧付款不追溯，成功还原后再次点击不应重复返料。
7. **保存重进与旧记录**：保存前后记录实际属性和材料数量，对比重进结果。旧记录可用备份测试物品复核，不应通过改写个人世界进行验收。

Debug 只用于准备物品、技能等测试条件。**验证扣料与付款账本时必须关闭免费制作/无限材料模式**，使用正常制作面板，让真实材料消耗完成；免费制作不能证明收费或返料路径正确。

原生配方调试图标面板如出现 `setPlaceholderText` 空引用，可避开该调试入口，使用物品列表生成器准备物品，再进入正常制作面板。这个调试 UI 异常不作为强化成功或失败的证据。

## 报告问题

请提供游戏 Build、模组版本、完整物品 ID、操作前后规格、裁缝等级、材料实际差额和最小复现步骤。涉及其他模组时列出其版本及加载顺序；日志仅保留相关片段，提交前去除本机路径、账号和存档等私人信息。

制作面板旧档位仍亮、动作已经播放或一条控制台命令成功，都不足以单独判断升级成功。请以目标实例的最终属性、记录与材料变化为准。
